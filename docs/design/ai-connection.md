# AI 服务：摘要与连接草稿

实现依据：[API 连接界面调研](../research/api-connection-ui-2026-09-18.md)。保留设置页 4+1 导航；连接区前移到用量页顶部。

## 展示与操作

- 日常只显示服务、当前模型、检测状态、“修改连接”和“检测连接”。有密钥但没有检测时明确显示“已配置 · 尚未检测”，不以绿点表示成功。
- “修改连接”行内展开表单。标签位于输入上方；官方服务隐藏固定地址，自定义服务要求兼容 Anthropic Messages。回复长度上限位于高级设置。
- 已保存的密钥不回传到 WebView。新密钥输入框留空表示保留，填写表示替换。“移除本机密钥”是明确的草稿操作，可反向切换或取消；保存后如有外部配置，按原优先级回退。
- “取消修改”只恢复连接草稿。“保存连接”只提交该连接，不保存或清除其他分区的未提交改动。全局保存也使用同一连接草稿提交路径。
- 检测不自动保存；修改模型、密钥、地址或高级选项后使旧检测结果失效。检测期间锁住连接字段和提交按钮，防止重复请求。延迟返回的旧检测结果不会覆盖更新后的页面。
- 浏览器静态预览只显示“请在桌面应用检测”，不伪造成功，也不发往真实服务。

## 后端接口

`cmd_settings_save_ai` 与 `cmd_settings_test_ai` 接收 `ConnectionDraft`：

- `api_key: null`：保留现有本地密钥；非空字符串：替换。
- `clear_saved_key: true`：移除本地覆盖，与新密钥互斥。
- `base_url`、`model`、`max_tokens`：正常覆盖字段。空地址/模型在 Rust 端表示沿用配置来源；界面提交要求用户提供有效地址与模型，避免误操作。

读取设置只返回已保存/有效密钥的布尔状态；`AiView::new` 总是移除返回对象中的密钥。`AiConfig::load_with_override` 使用现有回退来源解析草稿，不写配置。

## 检测边界

- 仅用户点击时调用 Anthropic Messages，发送固定的“Reply OK.”，输出上限 8，不包含系统人设、聊天历史、屏幕或记忆。
- 总请求期限 15 秒，不跟随重定向；响应体限制 64 KiB。成功要求有效的 assistant text message，HTTP 200 或 HTML 页面本身不算通过。
- 分类返回认证失败、权限不足、模型/请求不被接受、限流、网络错误、超时、不兼容回复、服务异常。前端不显示服务商原始错误正文，日志只记录状态和耗时。
- 成功请求的用量进入已有本地统计，记入 Chat 并标注 `connection_check`。
- 验证范围为一次文字对话，不等于工具调用、图片理解等能力均可用。不新增 OpenAI 或 Gemini 协议支持。

## 验证与产品自检

- 时刻：照料；回答服务是否可用，以及失败后如何修复。
- 常驻入口预算：连接区由四个输入和显隐按钮缩为两个操作；编辑时提供必要草稿控制，高级项折叠。未增加导航分区。
- 新请求仅通过明确的“检测连接”触发，旁边说明会产生少量用量；不修改能力默认值。
- 核心使用 wiremock 验证成功、认证/限流/格式失败、超时、不跟随重定向和密钥操作；请求与返回协议有审阅后的 insta 快照。
- 前端覆盖保留/移除/取消密钥、草稿校验、局部保存、检测失效与过期结果；app 测试覆盖密钥不回传。
- Linux 的完整可执行文件链接受现有 Windows COM 语音符号影响；类型检查、核心和设置模块测试可独立通过。Windows 原生运行仍需实机验证。
