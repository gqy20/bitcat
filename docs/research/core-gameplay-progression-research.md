# BitCat 核心玩法与成长系统调研

更新日期：2026-05-17  
目标：把“笨笨的智能机逐步变聪明”做成可感知、可积分、可升级的核心体验。

## 设计结论

BitCat 最适合的核心玩法不是传统 RPG 的“刷等级”，而是：

> 用户日常使用电脑 → BitCat 用有限能力陪伴/反应 → 用户获得 Bit 与默契 → 解锁新能力 → BitCat 变得更懂用户、更会帮忙、更会玩 → 用户愿意继续带着它生活。

这里的“升级”应该主要表现为 BitCat 的认知和权限逐步开放，而不是单纯数值变大。用户要感觉到它像一台刚开机的笨智能机：一开始只能做少量明确的事，后来逐渐学会聊天、记忆、跳舞、看屏幕、帮忙执行工具、看管 Agent。

最重要的取舍：

- 用“渐进启用”包装复杂能力，避免第一次打开就把 AI、截图、shell、热键、记忆全部砸给用户。
- 积分只奖励健康使用和真实互动，不奖励刷屏、长时间挂机或隐私敏感行为。
- 高风险能力不能只靠等级自动开放，必须同时满足用户明确授权。
- 能力解锁要有预告和仪式感，让用户知道“我的 BitCat 真的长大了”。

## 外部调研要点

### 渐进披露/渐进启用

UX 里的 progressive disclosure 主张先展示最必要的功能，把高级或低频功能延后，让新用户更容易学习、少犯错。BitCat 正好是功能密度很高的产品：如果把截图观察、记忆、shell、热键、Agent Watch 全部作为第一屏能力，会让用户既兴奋又不安。

对 BitCat 的启示：

- 第一小时只给“可爱、可控、低风险”的能力。
- 高级能力不藏死，而是在恰当场景里让 BitCat 主动提出：“我好像能学会这个，但需要你同意。”
- 设置页可以显示完整能力树，但默认只点亮当前阶段，锁住的能力给出简短预告。

### 自我决定理论：自主、胜任、关系

游戏动机研究里常用 Self-Determination Theory：玩家更容易长期投入，当体验满足自主感、胜任感和关系感。

对 BitCat 的启示：

- 自主感：用户可以选择让 BitCat 学什么、停用什么、忘记什么。
- 胜任感：用户完成日常任务、小游戏、专注时段后得到清晰反馈。
- 关系感：成长不是“我变强”，而是“我和 BitCat 更熟了”。

所以积分系统不应该像 KPI 仪表盘，而应该像“共同生活的痕迹”。

### 虚拟宠物：照料、回应、演化

Tamagotchi 类虚拟宠物的核心不是功能多，而是“我做了什么会影响它变成什么”。健康值、快乐值、照料失误、进化分支、关系等级，都在让用户相信宠物不是静态挂件。

对 BitCat 的启示：

- 不做饥饿/死亡这种强负担机制，避免把桌面陪伴变成压力源。
- 可以做轻量状态：电量、心情、好奇心、默契、熟练度。
- 演化结果来自真实使用习惯：常聊天的 BitCat 更会说，常跳舞的 BitCat 更爱表演，常打小游戏的 BitCat 更像搭档。

### 游戏经济：来源、池子、消耗

积分经济要有 sources、pools、sinks。只发不花会通胀，只花不发会挫败。BitCat 不需要复杂 F2P 经济，首版只需要一个软货币 `Bit` 加一个长期进度 `默契`。

建议：

- `Bit`：可花费货币，用于外观、动作、气泡主题、小游戏装饰。
- `默契`：不可花费经验，代表关系和能力熟练度，用于能力阶段解锁。
- `权限`：独立于积分，截图、剪贴板、shell、热键等必须用户授权，不能靠积分绕过。

## 核心循环

### 桌面陪伴循环

```text
开机/启动 BitCat
  → BitCat 做低打扰陪伴反馈
  → 用户聊天、工作、玩小游戏、触发面板、跳舞、专注
  → 获得 Bit / 默契 / 事件记录
  → BitCat 表现出一点变化
  → 解锁一个小能力或外观
  → 回到日常桌面
```

这条循环适合 Steam 首发，因为它不要求一次性做完整地牢游戏；现有功能已经能支撑。

### 能力成长循环

```text
用户经常使用某类能力
  → 对应熟练度上涨
  → BitCat 触发“我学会了”事件
  → 用户确认是否启用
  → 新能力进入日常循环
```

例子：

- 聊天 5 次 → 解锁“连续对话记忆提示”
- 跳舞 3 次 → 解锁“让 BitCat 自己编舞”
- 手动截图 3 次 → 解锁“屏幕观察试用”
- 使用面板 10 次 → 解锁“自定义动作推荐”
- Agent Watch 看管 3 次 → 解锁“任务进度提醒”

## BitCat 成长阶段

### 阶段 0：刚醒的功能机

时间：前 10-20 分钟  
目标：低压力、可爱、立即明白。

可用能力：

- 桌宠待机、拖拽、贴边吸附。
- 基础情绪动画。
- 点击/手柄基础互动。
- 简单问候气泡。
- 一个非常小的小游戏或抛接互动。

禁用或隐藏：

- 后台截图。
- 长期记忆。
- shell / launch / hotkey 工具。
- Agent Watch。

用户感受：

> 它还挺笨，但很可爱，而且不会乱动我的电脑。

### 阶段 1：能聊的智能机

触发：完成首次聊天、累计 10-15 分钟使用。  
核心变化：BitCat 开始能理解自然语言，但记性很短。

解锁：

- AI 流式聊天。
- 气泡 Markdown。
- 基础 TTS 可选。
- 简单 mood reaction。

限制：

- 不自动记住长期信息。
- 不主动读取屏幕。
- 不调用系统工具。

仪式：

- BitCat 说：“我好像能听懂你说话了，但我可能会忘得很快。”

### 阶段 2：有小记性的手机

触发：多次聊天、用户手动确认“允许记住偏好”。  
核心变化：BitCat 开始形成用户画像和短期记忆。

解锁：

- 短期对话记忆。
- user.yml 设置引导。
- 长期记忆审查面板。
- “记住/忘记”显式交互。

安全约束：

- 首次启用要说明保存位置。
- 设置页必须能审查和删除。
- AI 不能把记忆当作不可更改事实。

仪式：

- “我记住了。要是我记错了，你可以把这条划掉。”

### 阶段 3：会玩的智能伙伴

触发：跳舞、小游戏、面板使用达到轻量门槛。  
核心变化：BitCat 从聊天工具变成可玩的宠物。

解锁：

- 舞蹈播放。
- AI 编舞 `perform_dance`。
- Snake/Memory/Catch/Battle 入口。
- 可购买/解锁舞步、气泡主题、表情。

积分消耗开始出现：

- Bit 购买视觉奖励。
- 默契解锁更自然的表演行为。

用户感受：

> 它不只是回答问题，它有自己的小把戏。

### 阶段 4：会观察的助手

触发：用户多次手动截图，且明确授权观察。  
核心变化：BitCat 可以在用户允许时理解屏幕上下文。

解锁：

- 手动截图分析。
- 最近截图记录。
- 可选后台截图观察。
- 屏幕活动摘要。

安全约束：

- 后台截图默认关闭。
- 每次开启要显示清楚：截图会发给哪个模型服务、保存在哪里、保留多久。
- 提供“暂停观察 1 小时/今天/永久关闭”。

仪式：

- “我可以帮你看一眼屏幕，但只有你点头的时候。”

### 阶段 5：会帮忙的工具机

触发：用户在设置中启用工具权限，且完成安全说明。  
核心变化：BitCat 可以执行受控工具，但不是默认全能。

解锁：

- `launch_program`
- `send_hotkey`
- `read_clipboard`
- `recent_screenshots`
- 受限 `shell`

设计原则：

- 每个工具都有第一次使用确认。
- 高风险工具有权限等级：只读、低风险动作、需确认动作、禁止动作。
- 能力树里不说“解锁 shell”，说“解锁帮你操作电脑的能力”，减少技术恐惧。

仪式：

- “我能帮你按按钮了，但危险的事我会先问。”

### 阶段 6：成熟搭档

触发：长期使用、Agent Watch/任务看管、多个能力熟练。  
核心变化：BitCat 从宠物变成有生活痕迹的桌面搭档。

解锁：

- Agent Watch 提醒。
- 更主动的上下文建议。
- 高级记忆总结。
- 个性化日常问候。
- 组合式自动建议：比如“你刚才看了报错，要不要我打开最近截图/终端/项目？”

限制：

- 主动性要低打扰。
- 所有主动建议都可关闭。
- 不让 AI 自行扩大权限。

## 积分与升级系统

### 两条进度

`Bit` 是软货币：

- 能获得、能消费。
- 用于外观、动作、气泡、小游戏装饰、称号。
- 不购买危险权限，不购买核心安全绕过。

`默契` 是经验/关系：

- 不消费，只累计。
- 用于阶段解锁、台词变化、行为变化。
- 来自真实互动和稳定使用。

### Bit 来源

建议首版来源：

| 来源 | 奖励 | 上限 |
| --- | --- | --- |
| 每日启动 | 20 Bit | 每天 1 次 |
| 首次聊天 | 10 Bit | 每天 3 次 |
| 完成专注时段 | 30 Bit | 每天 4 次 |
| 玩小游戏 | 10-40 Bit | 每天 150 Bit |
| 舞蹈/互动 | 5-15 Bit | 每天 60 Bit |
| 手动截图分析 | 10 Bit | 每天 5 次 |
| Agent Watch 完成任务 | 20-50 Bit | 每天 3 次 |
| 连续使用天数 | 阶梯奖励 | 断签不惩罚，只重置 bonus |

不建议奖励：

- 聊天字数。
- 截图次数无限刷。
- shell 执行次数。
- 后台观察时长。
- 纯挂机时长。

### Bit 消耗

首版消耗池：

- 皮肤色板。
- 气泡主题。
- 舞步动作。
- 问候语包。
- 小游戏主题。
- 贴边形态特效。
- “回忆相册”装饰边框。

不要把以下内容做成 Bit 消耗：

- 隐私/安全开关。
- 删除记忆。
- 暂停观察。
- 基础可用性功能。
- 已在商店页承诺的核心能力。

### 默契来源

默契比 Bit 更慢：

| 行为 | 默契 |
| --- | --- |
| 完成一次自然聊天 | +1 |
| 用户纠正/编辑一条记忆 | +2 |
| 完成一次小游戏并结算 | +2 |
| 触发一次舞蹈/表演 | +1 |
| 让 BitCat 帮忙完成一次明确任务 | +3 |
| 连续 3 天使用 | +5 |
| 用户主动关闭某个能力并保留设置 | +1 |

最后一条看起来奇怪，但很重要：尊重用户边界也应该成为关系的一部分。这样 BitCat 的“懂事”不是靠侵犯权限换来的。

### 升级曲线

建议首版 6 个阶段：

| 阶段 | 默契门槛 | 用户可感知变化 |
| --- | ---: | --- |
| Lv0 功能机 | 0 | 只会基础互动 |
| Lv1 会聊天 | 5 | AI 对话开放 |
| Lv2 小记性 | 15 | 记忆与画像开放 |
| Lv3 会玩 | 30 | 舞蹈/小游戏奖励开放 |
| Lv4 会观察 | 55 | 截图分析能力开放，但需授权 |
| Lv5 会帮忙 | 90 | 工具能力开放，但需逐项授权 |
| Lv6 搭档 | 140 | Agent Watch/主动建议开放 |

曲线要故意短一点，让玩家前 2 小时至少经历 2-3 次成长。后期再用精通、收藏、成就拉长寿命。

## 能力树草案

```text
BitCat Core
├── 说话
│   ├── 流式聊天
│   ├── TTS
│   └── 情绪收尾
├── 记住
│   ├── 短期记忆
│   ├── 长期记忆
│   └── 记忆审查/删除
├── 表演
│   ├── 默认舞蹈
│   ├── AI 编舞
│   └── 音乐响应
├── 玩耍
│   ├── Snake
│   ├── Memory
│   ├── Catch
│   └── Battle
├── 观察
│   ├── 手动截图
│   ├── 最近截图
│   ├── 后台观察
│   └── 活动摘要
└── 帮忙
    ├── 打开程序
    ├── 发送热键
    ├── 读剪贴板
    ├── 受限 shell
    └── Agent Watch
```

UI 上不要一次铺这么满。设置页可以有“成长树”，日常气泡只提示最近一个可解锁目标。

## 首发 MVP

建议先实现最小版本：

1. 本地 `ProgressStore`
   保存 `bit_balance`、`synergy_xp`、`level`、`unlocked_features`、每日计数器。

2. 事件采集
   接入已有事件：聊天完成、舞蹈播放、小游戏结算、手动截图、设置开关、Agent Watch 完成。

3. 能力门槛
   用配置表定义能力：`feature_id`、`level_required`、`permission_required`、`unlock_copy`。

4. 解锁气泡
   当满足门槛时，弹出一次短事件：“BitCat 学会了 X”。需要授权的能力进入确认流程。

5. 奖励商店
   先只做视觉奖励：气泡主题、舞蹈、称号。不要做复杂装备。

6. 设置页进度
   显示当前等级、下一解锁、Bit 收支、已解锁能力。

## 技术映射

可新增 core 模块：

```text
core/src/progression.rs
  ProgressStore
  ProgressEvent
  FeatureUnlock
  RewardLedger
```

本地文件：

```text
~/.bitcat/progression/progress.json
~/.bitcat/progression/ledger.jsonl
```

建议事件：

```rust
enum ProgressEvent {
    AppLaunched,
    ChatCompleted,
    MemoryReviewed,
    DancePlayed,
    GameCompleted { game_type, outcome, score },
    ScreenshotManualCompleted,
    AgentWatchCompleted,
    SettingEnabled { key },
    SettingDisabled { key },
}
```

设计注意：

- 收支写 ledger，方便排查和防重复奖励。
- 每日上限存在 progress store 中，按本地日期重置。
- 不把 token 用量直接当奖励来源，避免鼓励浪费 API。
- unlock 状态要和权限状态分开：`unlocked != enabled`。

## 风险与反例

- 过度锁功能：买了 Steam 版却发现核心 AI 还要刷 5 小时，会差评。解决：前 30 分钟开放核心聊天，后续锁的是高级便利和主动性。
- 积分变 KPI：用户为了点数刷对话/截图，反而破坏陪伴感。解决：强日上限，奖励多样化，弱化排行榜。
- 隐私换成长：不能用“开启截图观察奖励更多”诱导用户交出权限。解决：手动截图可以给少量奖励，后台观察不给持续收益。
- 笨得太久：用户想看变化，但不能忍受工具真的不好用。解决：笨是人格表现，不是产品缺陷；核心操作必须顺滑。
- 解锁无感：只在设置页多一个按钮不够。解决：每次解锁配动画、台词、一次示范。

## 下一步建议

第一步先做“成长系统薄片”，不碰复杂地牢：

1. 定义 `ProgressEvent` 和本地 `ProgressStore`。
2. 接入 5 个现有事件：启动、聊天、跳舞、小游戏、手动截图。
3. 做 6 级能力门槛，但只真正 gate 3 个低风险能力：AI 编舞、气泡主题、小游戏主题。
4. 高风险能力只显示“已具备学习条件，需要你授权”，不自动开启。
5. 设置页新增“成长”tab。

这样一周内就能验证：用户是否喜欢看 BitCat 从“笨手机”成长为“智能伙伴”。
