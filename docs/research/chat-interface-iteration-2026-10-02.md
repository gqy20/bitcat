# 对话界面体验与迭代评估

日期：2026-10-02。依据：[对话界面设计调研](chat-interface-design-2026-10-02.md)、[产品规范](../product/design-spec.md)、[文字规范](../design/typography.md)。本轮先实现猫旁短回应与主动会话，再通过真实前端体验继续修正。

2026-10-03 后续：下文记录的多入口混写问题已通过统一 FIFO 和请求编号修复；后台收尾与长期记忆事务也已调整。当前实现见[对话执行架构](../architecture/chat-runtime.md)，表达样本与原生验证状态见[后续验收记录](chat-native-validation-2026-10-03.md)。本页保留当时的评估和测试数量。

## 评估结论

连续聊天已能直接完成：回复结束后输入保留，最近问答可回看，失败可用原草稿重试，停止和收起具有不同的行为。窗口层级更轻，猫、用户消息、回复和输入区的关系更清楚。

本轮通过浏览器中的生产 HTML/CSS/JS、模拟 IPC 和 Rust 回归验证了这些行为。没有完成 Windows WebView2 原生体验验收，也没有多人用户测试；当前尺寸、留白和动效是待原生验证的设计参数。

## 当前状态契约

| 状态 | 可见内容 | 尺寸与退出 | 内容保护 |
| --- | --- | --- | --- |
| 猫的短回应 | 简短文字，沿用原有通知入口 | 通常 300×120；普通回应约 15 秒退场，既有 Agent 更新约 8 秒 | 主动聊天、阅读和生成时避让；通知不进入问答历史 |
| 主动聊天 | 最近两轮已完成问答、当前真实问题和回复、常驻输入 | 默认 400×340；生成字符不推动窗口连续变大；用户主动收起 | 草稿不因暂停输入或收起而清空；上翻阅读时不强制滚到底部 |
| 展开阅读 | 当前长回复、代码与表格，以及可回看的最近问答 | 默认 440×560；进入时定位当前问题与回复开头；“返回聊天”回到聊天尺寸 | 不自动消失；用户交互期间暂停跟随猫；收起再开恢复阅读状态与位置 |

尺寸单位为逻辑像素。手动尺寸偏好继续保留；过小的窗口会为正文、输入和错误说明预留实际空间。持续跟随在主动交互期间暂停，打开或调整尺寸时仍进行定位与屏幕边界修正。

最近问答仅存在当前气泡页面内存中，保留两轮历史与当前一轮，不新增磁盘聊天记录。模型上下文继续使用原有记忆系统；这些可见问答没有从截断后的记忆摘要反向拼接。语音等入口没有提供用户原文时，界面只展示已知回复。

## 两轮改动与体验中继续修正的问题

### 第一轮：建立连续聊天

- 去掉内框、网格纹理和多层阴影，保留暖色实底、弱边界和单层阴影。
- 顶部标题与收起独立排列，避免盖住第一行内容；箭头指向猫。
- 单行输入改为可增长的多行输入。Enter 发送，Shift+Enter 换行；中文组合输入不触发发送。
- 输入区在生成和完成后保留；生成时发送位置复用为停止，仍可先写下一句。
- 发送失败保留草稿，并明确说明没有发出及如何重试。正常工具进度弱化为一行，失败保持可见。
- 区分生成保护和交互保护，回复完成后仍保护正在聊天或阅读的内容。

### 第二轮：恢复上下文与修正边界

- 保留最近两轮真实问答，停止的部分回复有轻文字标记。首次普通通知不会被误归入历史。
- 收起后保留问答、草稿、阅读状态和滚动位置；迟到的轮询或回复结束不会重新打开用户已收起的窗口。
- 展开阅读按当前问题的真实几何位置定位。去掉程序滚动的平滑行为，避免尺寸调整与滚动目标相互干扰。
- 最小手动窗口中，三行输入与发送失败说明曾挤掉正文并裁切输入；改为按实际区域高度撑高。
- 静态失败说明也走开始、正文、结束协议；空正文冷启动不会被当成持续生成。
- 回复结束携带不可变正文快照，避免收起后的普通通知覆盖最终回复。
- 停止会移除待执行请求，并丢弃运行中的模型流 future，阻止它继续推进后续工具。已经开始的外部动作不能靠停止按钮撤销。
- 停止确认前保留下一句并暂缓发送；停止请求失败时恢复停止入口并说明如何重试。旧结束或取消事件不能终止刚提交的新一轮。

### 用户预览反馈后的细化

去掉没有提供额外信息的“和猫聊聊”标题。展开与复制保留 32×32 点击区域，使用 16px 线形图标；阅读时切换为收回图标，复制成功短暂显示勾。操作名称保留在悬停提示与辅助标签中。发送、停止和失败说明继续使用文字。

细化后，对话相关 67 项回归与共享排版检查通过。局域网浏览器核对标题移除、图标尺寸、阅读切换，以及模拟复制成功后的反馈和标签；SVG 没有被状态更新替换成文字。

随后精简另外三处冗余：首次空状态去掉副说明，只留“设个提醒”和“看看最近”两个开头；只有已有可见问答时才显示“继续聊”。复制、展开和收起共用顶部操作区，删除底部操作行；高度计算同步改为测量实际顶部高度。发送等待只显示按钮“发送中”，失败原因与草稿恢复说明继续保留。

该轮 67 项对话回归、语法与共享排版检查通过。浏览器实测：440×560 阅读态的正文可视高度由 385px 增至 422px，当前问题仍对齐内容顶部；260px 窄窗口中，停止状态和图标在同一排，三行草稿与发送失败说明均完整可见，窗口约 260×311，正文仍有 78px 可读高度。等待提交确认时没有重复提示，失败后仍能直接重试。截图为 `.playwright-cli/chat-iteration/compact-short.png`、`compact-reading.png` 和 `compact-narrow.png`。

### 处理状态的位置与切换

思考、普通工具进度和停止状态统一在顶部左侧，互相替换。使用轻圆点和普通字重文字；取消原来位于输入框上方的跳动点。右侧操作保留完整命中区域，主动会话顶部固定 32px。正文开始输出后撤下思考提示；未完成的工具进度继续显示，普通工具完成后退出。舞蹈交接仍沿用原有短提示退场。

失败和权限受限继续在正文完整显示，生成结束后保留到新的步骤、下一轮或用户收起。已停止或已收起的会话忽略迟到的工具状态，避免重新显示正在处理。停止请求失败时恢复回复状态，顶部不会继续显示“已停止”。

新增 8 项真实状态转换回归，对话测试共 75 项通过。浏览器实测：思考切换为工具进度时，400×340 窗口、正文位置及输入位置均不变；260px 窄窗口保持 32px 顶部，过长普通进度单行省略且有完整悬停说明，长失败文案在正文换行。模拟阅读时到达进度事件，440×560 阅读态保持 422px 正文高度，scrollTop 70 在进度出现与退出后保持为 70。截图为 `.playwright-cli/chat-iteration/header-progress-working.png`、`header-progress-narrow.png` 和 `header-progress-blocked.png`。

静态预览的处理场景同步使用开始、工具事件与结束协议。每次加载为模拟脚本、生产脚本和样式附加预览版本参数，避免浏览器沿用旧资源。

### 颜色语义的收敛

权限限制与等待确认改为琥珀色，执行失败继续用砖红色；列表符号回到正文色，链接保留蓝色；复制成功的勾短暂使用深绿。普通处理进度继续保持灰褐色，纸面、正文和用户浅块保持原有配色。实现值、对比度与验收结果见 [气泡配色规范](../design/chat-bubble-colors.md)。预览补充“文件访问受限”场景，便于与“提醒失败”对照。

## 浏览器体验证据

体验台加载生产页面、字体、Markdown 渲染器、样式和脚本，仅在 Tauri 边界模拟事件、累计文本、提交失败和窗口尺寸。没有调用真实 AI 服务。每次改动用新的 URL 重新加载，并核对父页面、气泡页面 URL、标题和关键 DOM。

| 场景 | 观察与结果 |
| --- | --- |
| 短回复后追问 | 400×340，输入始终可用；当前问题独立显示；下一轮不需要先点“继续说” |
| 连续四轮 | 只保留前两轮和当前一轮，当前回复不重复，普通通知没有混入历史 |
| 两轮历史后展开长文 | 440×560，当前问题对齐正文滚动区顶部，回复开始距顶部约 51px |
| 独立长历史复核 | 两轮历史约 1402px 高，展开后仍从当前问题与第一段开始 |
| 阅读中收起、短通知、再打开 | 测试中的 scrollTop 389 保持为 389；草稿、阅读模式及完整回复恢复；返回聊天保持该位置 |
| 多行草稿发送失败 | 两行原文完整保留，界面显示恢复说明，发送按钮可直接重试 |
| 生成中停止并保留下一句 | 只提交原问题，保留已写下一句，生成结束并显示“已停止” |
| 手动 260×240、三行草稿、已有两轮历史、发送失败 | 修正后撑高到约 260×353；正文仍有约 83px 可读高度；输入和发送位于窗口内 |

临时截图在 `.playwright-cli/chat-iteration/`：`v2-short-reply.png`、`v2-send-failure.png`、`v2-stopped-draft.png`、`v3-reading.png`、`v3-narrow-fixed.png`。独立阅读验证图是 `.playwright-cli/read-history-layout-fixed.png`。这些是浏览器体验证据，猫的图像和背景由体验台组合，不是 Windows 原生窗口截图。

可重用体验入口已接入项目的静态预览体系：在 `app/frontend` 启动既有 4178 HTTP 服务，打开 `/tools/chat-preview.html`。页面直接读取生产气泡并注入示例边界，不需要临时专用服务器。启动和局域网访问方法见 [开发指南](../guide/getting-started.md#静态预览入口)。

## 验证与后续优先级

前端回归直接加载生产页面和脚本，覆盖草稿、IME 组合事件、重复提交、停止、晚到确认、收起恢复、旧轮询、滚动、最近问答和结束快照。Rust 回归覆盖生成与交互独立保护、通知避让、排队取消、取走队列后取消及运行 future 被丢弃。

首轮完整检查：前端 29 个文件、339 项测试通过，其中 33 项直接验证生产气泡生命周期；`make test-app` 184 项通过、4 项跳过；`make build` 成功。后续界面细化按上文记录定向验证，最新对话回归共 75 项。共享排版检查覆盖 12 个生产样式文件，JavaScript 语法与 diff 检查通过，静态资源由 `xtask prepare-frontend` 同步到构建输入目录。

提交前最终核对：前端全量 29 个文件、347 项测试通过；`cargo clippy --workspace --all-targets -- -D warnings` 通过，文档本地链接与变更格式检查通过。

下一步优先进行 Windows 实机验收：中文候选框、焦点与置顶、100%/150%/200% DPI、多显示器边缘定位、原生滚轮转发、拖动调整尺寸，以及停止后立即继续聊。浏览器组合事件测试不能证明真实输入法和原生窗口行为。

代码复核还发现原有的并发入口限制：语音/手柄对话与文字对话由不同循环启动，共用正文缓存。两种入口同时触发可能混写回复，本轮没有统一这些执行入口。后续应串行执行全部对话，或为完整开始、正文与结束协议绑定请求编号，并用双入口回归验证。

设计上继续观察两点：400×340 对日常短对话的占用是否合适；只保留最近两轮是否够用。先用实际连续对话评估，再决定长期历史、独立阅读窗口或新的入口。角色反应与文字出现的节奏也值得下一轮联动观察。

## 产品自检

- 时刻：主要是互动，也修正陪伴通知与互动之间的边界。
- 四个疑问：“刚才干了什么”更清楚，真实问题、回复、工具状态和停止结果可见。
- 预算：设置新增 0；主动会话可见入口 +0 / -1，隐藏原有“继续说”，发送位置复用停止；首次空状态快捷入口从 3 个减至 2 个；顶部合并既有操作，不新增入口。历史与反馈均为只读内容。
- 文案：新增文案使用聊天、收起、停止、复制和阅读等普通用语；技术诊断留在日志。
- 恐慌测试：没有新增观察、授权或收费能力；用户收起选择和草稿受到保护。
