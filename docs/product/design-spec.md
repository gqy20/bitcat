# BitCat 产品设计规范（Product Design Spec）

> **定位**：所有「用户可见」改动的**验收标准**。改任何窗口界面、设置项、文案、通知、默认值、入口之前必读。
>
> **与其他文档的关系**：
> - [docs/roadmap.md](../roadmap.md) 的「产品视角」节 = 判断基准（*为什么*）；本文件 = 可执行细则（*怎么做*）。两者冲突时以本文件为准，本文件与实际代码冲突时先改文档再动手。
> - [docs/architecture/design-tradeoffs.md](../architecture/design-tradeoffs.md) 记录技术取舍；本文件记录**产品取舍**。
>
> **一句话**：陪伴优先，信任至上，能少勿多。用户价值 ≠ 功能数量，理解成本是真实成本。

---

## 0. 适用范围

**受本文件约束**：全部窗口（pet / bubble / panel / voice / settings / game / agent-watch / notification / camera / pet-inbox / glow）的界面与文案、任何气泡和通知的内容与时机、任何默认值、任何用户可触达的入口数量。

**不受约束**：纯后端逻辑、内部日志格式、测试代码、构建脚本。但注意：内部日志若直接展示给用户（如设置页"用量与诊断"），其**展示层**受约束。

---

## 1. 产品原则（P0 —— 违反任一条不予合并）

- **P1 用户价值 ≠ 功能数量**。新增任何功能前先回答两个问题：*为此要删掉/收纳什么？* *谁的使用数据证明有人需要？* 答不上来就不做，或先进专家模式。
- **P2 三时刻模型**。每项改动先声明属于哪个时刻：**陪伴**（~95%，"它在呢"）、**互动**（~4%，"陪我玩会儿"）、**照料**（<1%，"它值得信任吗"）。跨时刻的功能拆开评估；照料时刻的改动优先级高于另外两者之和。
- **P3 信任是第一资产**。高权限能力必须满足四可：**可见**（用户随时能查它在干什么）、**可关**（显式开关）、**可收回**（≤2 次点击）、**可解释**（一句不含术语的话说明它会做什么）。
- **P4 人话原则**。通用界面零工程术语（对照表见 §4.1）；面向开发者的功能允许开发者词汇，但必须附一句人话解释。
- **P5 默认值倾向用户**。每个能力默认关闭或最小化，除非通过恐慌测试（§5.1）。越强的能力，越应该由用户第一次亲手打开。
- **P6 入口预算**。同一时刻的功能入口有数量上限（§3.5）；新入口必须有旧入口让位。

## 2. 用户模型与核心叙事

- **画像**：想要桌面陪伴的 cozy / productivity 用户。会装 Steam 游戏，不读日志，不理解 token，**对"AI 偷看屏幕"高度敏感**。一部分用户是开发者（Agent Watch 的受众），但产品整体不为开发者优化。
- **核心循环**：开机 → 猫在角落安静待着 → 偶尔说句话 / 玩一局 → 关机。**这个循环里用户需要碰设置的次数趋近于零**——设置页是为"心里冒出疑问的时刻"服务的，不是功能面板。
- **四个疑问**（照料时刻的信息架构锚点，一切用户界面围绕它们组织）：
  1. "它在偷看我的屏幕吗？"（权限）
  2. "它记住了我什么？"（记忆与隐私）
  3. "这个月花了多少钱？"（成本）
  4. "它刚才干了什么？"（行为审计）

## 3. 信息架构规范

### 3.1 设置页 = 4+1

四个用户分区按四个疑问组织，加一个折叠的专家模式：

```text
① 它能做什么     权限总览仪表（设置页首屏），含一键"全部收权"
② 它记住了我什么 记忆按人话展示 + 查看 / 导出 / 删除
③ 它花了多少钱   今日 / 本月成本与去向（对话 / 观察 / 摘要）
④ 它怎么陪着我   品种 / 舞蹈 / 游戏 / 提醒（唯一"开心"的分区）
⑤ 专家模式       默认折叠，单次点击进入；编辑提示词、诊断日志、
                  hook 修复、token 链路明细、日志路径等全部收纳于此
```

> **现状**：设置页仍是 11 个按代码模块命名的 tab（`memory` / `prompts` / `agent-watch` / `usage`…）。
> 【F1 落地中】迁移映射表见 roadmap Track F1；在 F1 完成前，新设置项**不允许**加入现有 tab，一律先按 4+1 归类。

### 3.2 控件预算（zero-sum）

用户分区可交互控件总数 ≤ **20**。加一个必须移除或收纳一个；"先加上再说"不成立。

### 3.3 专家模式准入

满足任一条即只能进专家区，不进用户区：

- 用户需要理解 YAML / JSON / 目录路径才能安全使用；
- 属于开发者工作流（编辑提示词、修复 hook、查看链路明细）；
- 调试用（宠物事件决策日志、资源采样、hook doctor）。

### 3.4 首屏原则

设置页第一屏必须直接回答四个疑问各一张卡片，而不是模块统计。"AI 已连接 / 截图观察：开 / 记住了 12 件事 / 本月 ¥6.20" 优于任何图表。

### 3.5 入口预算

- **panel**：主推 **1 个**游戏（当前为 Invasion）+ **1 个**"猫的游戏库"聚合入口；8 个游戏并排是遗留形态【F3 落地中】。
- **托盘右键菜单**：≤ 8 项，超出即分组。
- **panel 功能网格**：2×2 起步，超过 2×3 必须重新设计信息架构而不是加格子。

### 3.6 深度规则

- 任何设置项 ≤ **2 次点击**可达（首屏分区 → 目标项）。
- 收回任何权限 ≤ **2 次点击**；"全部收权"是首屏一级操作。

## 4. 文案规范（用户语言）

### 4.1 术语对照表

通用界面**禁用**左列词汇，用右列替换（对照表随产品演进补充；拿不准的新词先进表再进界面）：

| 工程语（禁用于用户区） | 用户语 | 备注 |
|---|---|---|
| Token / 最大 token | 用量 / 回复长度上限 | 金额永远优先于 token 数 |
| Base URL | 服务地址（可选） | 附"不确定就留空" |
| JSONL / JSON / YAML / schema / IPC / crate / manifest | —— 一律不出现 | 需要指代文件时说"记录文件" |
| Hook / 修复 Claude Hook / 需要 Hook | 连接 / 修复连接 / 连接异常 | 开发者分区可用原词，但配一句人话 |
| 宠物事件 | 它的反应 | |
| Agent Watch | 编程助手看管 | 面向开发者的功能，保留原词时配人话副标题 |
| Vision / 截图观察（作为功能名） | 屏幕观察 | "它会定期看到你的屏幕" |
| 权限 gate / PermissionHook | 授权确认 | |
| AppData / `~/.bitcat` | 数据目录（带"打开位置"按钮） | 路径永远可点开，不要求用户记忆 |

**例外**：`API Key` 保留原词——用户必须自己去申请它，回避这个词反而增加困惑；但入口处必须有一句"这是什么、去哪拿"的说明。

### 4.2 错误消息三段式

任何用户可见的失败输出按此结构：**发生了什么**（人话，不贴原始错误码）→ **为什么**（一句话，可省）→ **怎么办**（可执行动作，如按钮或"去设置里填写密钥"）。技术细节折叠或进日志，不进正文。

### 4.3 数字人话化

- 金额用 `¥6.20`，不用 `1,240,000 tokens`；token 数只作为次要信息。
- 频次用"每 30 秒一次 / 每天 3 次"，不用裸计数。
- 时间用相对时（"5 分钟前"），绝对时间仅提醒列表需要。

### 4.4 语气

安静的伙伴：不用感叹号，不用连续 emoji，不卖萌轰炸（一个语境最多一个猫相关表达）。按钮用动词（"删除"不是"删除提醒？"），标题用名词，确认框正文承担解释职责。

## 5. 默认值与权限规范

### 5.1 恐慌测试（Panic Test）

每个**新默认值**和**新入口**合并前必须过一遍新用户时间线：

```text
T+10s   托盘出现猫              → 可爱 ✅
T+60s   对话要 API Key           → 学习成本，可接受
T+5min  气泡："我看到你在写代码"  → 恐慌点：截图观察此时必须是"用户亲手打开过"的
T+1day  打开设置                 → ≤2 次点击能回答四个疑问，否则认知瘫痪
```

规则：**每个能力 = 一句人话解释 + 一个显式开关 + 默认值倾向用户**。结论写进 PR 描述。

### 5.2 权限分级表

对齐当前 16 个内置工具；分级变更属于产品决策，需在本表登记：

| 级别 | 覆盖 | 默认状态 | 首次呈现方式 |
|---|---|---|---|
| **观察** | 截图观察（recent_screenshots / vision 链路） | 【F3 改造中】首次启动向导里由用户亲手开启 | 权限向导第 2 步，附演示截图说明它"看到"什么 |
| **观察** | 摄像头观察 | **默认关闭** | 设置页分区①，开启前展示保守描述承诺 |
| **执行** | shell / read_file / 剪贴板 / send_hotkey / force_foreground | 逐次确认（PermissionHook 拦截危险命令） | 权限向导第 3 步声明，运行时逐次确认 |
| **通信** | launch_program / start_game / 提醒 | 开（打开本地程序属用户显式指令） | 无需授权话术 |
| **纯本地** | 舞蹈 / 游戏 / 记忆查询 | 开 | 无需授权话术 |

### 5.3 收回路径

任何授权 ≤2 次点击收回；首屏提供"全部收权"。收回后**不得**在 24h 内反复弹窗请求重新开启（最多在设置页显示一行安静提示）。

### 5.4 数据权利（D3 落点）

记忆、截图、摄像头记录、日志、积分、提醒六类数据在分区②拥有统一的**查看 / 导出 / 删除**入口。删除是硬删除（记忆走软删除时必须在 UI 呈现为"已删除"并不可见）。

## 6. 通知与打扰规范（陪伴时刻保护）

- **分级**：`静默`（默认，绝大多数行为）→ `轻提示`（气泡，自动消失，不打断输入）→ `需要动作`（通知岛，带按钮）。跨级使用必须给理由。
- **频率上限**：沿用现有节流机制（`MoodPolicy` 的 TTL/优先级/节流、`agent_nudge` 的等待与完成策略）；新增通知类型必须接入同一套节流，不允许自建旁路。
- **允许打扰的时刻**（白名单）：用户刚提问后、需要授权确认时、用户自建的提醒到期、Agent Watch 显式订阅的会话状态变化。
- **惊喜要稀疏**：宠物主动搭话 / 自发表演类行为必须有冷却时间（以 config 数值为准），同一天不重复同类惊喜。
- **免打扰区**：全屏检测、game 窗口运行中，通知岛降级为静默计数。
- **声音**：默认静音；按来源分级配置（已有实现），新增声音必须默认关。

## 7. 新功能准入清单（Feature Admission Checklist）

任何用户可见的新功能/新设置/新入口，合并前逐项打勾并写进提交或 PR 描述：

```text
[ ] 一句话人话解释：念给不写代码的朋友听，能懂
[ ] 属于哪个时刻（陪伴/互动/照料）？改变了哪个疑问的答案？
[ ] 恐慌测试结论（若涉及默认值或新入口）
[ ] 开关在哪？收回路径 ≤2 次点击？
[ ] 控件/入口预算：加了什么、删了或收纳了什么（zero-sum 证明）
[ ] 文案过 §4.1 对照表 + 三段式检查
[ ] 若该领域已有 F2 使用数据：引用数字；无数据支撑的新功能默认进专家模式
```

"技术上行得通"不构成准入理由。**砍掉一个功能是合法且受鼓励的贡献**，附上 F2 数据即可。

## 8. 度量（本地数据，不上传）

产品决策以本地 JSONL 为事实来源，**不引入任何 analytics / 遥测服务**：

| 数据源 | 回答的问题 | 健康度红线 |
|---|---|---|
| `~/.bitcat/logs/points_events.jsonl` | 舞蹈/游戏/提醒/夸奖的真实频次 | 连续 14 天零使用的功能进入砍/藏评审 |
| `~/.bitcat/logs/tool_events.jsonl` | 16 工具中 AI 实际调用了哪几个 | 无人调用的工具从 prompt 引导中移除 |
| `~/.bitcat/logs/token_usage.jsonl` | 成本花在哪条链路 | 单链路占比 >70% 时优先优化该链路 |
| `~/.bitcat/logs/reminder_events.jsonl` | 提醒完成率 vs 无视率 | 无视率 >50% 的提醒类型重新设计或移除 |
