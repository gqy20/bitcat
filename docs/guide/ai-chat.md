# AI 对话与记忆系统

## 触发对话

有三种方式可以与 AI 对话：

| 方式 | 触发方法 | 标记 |
|------|---------|------|
| 手柄 | 按 **Start** 键 | 自动发送"你好！有什么可以帮你的？" |
| 鼠标 | 点击猫咪嘴巴区域 → 弹出输入框 → 输入文字 → Enter 发送 | `[chat]` |
| 语音 | 按住 **Y** 键说话 → 松开后识别文字自动发送 | `[voice]` |

三种方式最终走同一条 AI 对话管线，共享记忆和上下文。

## 对话流程

1. 触发后猫咪切换到 **Talk** 状态
2. 气泡窗口在猫咪上方弹出，显示流式 AI 回复
3. 如果已在设置中开启 TTS，AI 回复结束后自动朗读
4. 猫咪根据回复内容自动切换表情：
   - 包含"哈哈"、"😄"、"喵"等 → **Happy**
   - 包含"错误"、"失败"、"抱歉"等 → **Confused**
   - 其他 → 恢复 **Idle**
5. 气泡 15 秒后自动隐藏

## 气泡窗口

气泡是猫咪上方的透明窗口，用于显示 AI 回复和聊天输入框。

### 浏览回复

- 气泡高度会根据内容自动调整（短文本 140px，长文本最高 340px）
- 超长内容可**鼠标滚轮**或**键盘方向键**滚动浏览
- 向上滚动时自动锁定位置（不会被新内容冲走），滚回底部自动解锁
- 也可以**手动拖拽右下角**调整气泡大小，双击右下角恢复自动大小

### 聊天输入框

有三种方式打开输入框：

1. **点击猫咪嘴巴区域**
2. **双击气泡任意位置**
3. **AI 回复结束后自动展开**（可直接追问）

输入框空闲 **5 秒**后自动收起。按 Enter 发送，按 Esc 关闭。支持中文 IME 输入。

### 流式显示

AI 回复采用流式渲染，每 120ms 从后端拉取新文本。如果流结束事件丢失，连续约 1 秒无新内容会自动判定结束（稳定检测兜底）。

## AI 能力

AI 拥有 10 个内置工具，可以执行实际操作：

| 工具 | 功能 | 示例 |
|------|------|------|
| `launch_program` | 启动程序 | "帮我打开 VS Code" |
| `shell` | 执行 Shell 命令 | "查看当前目录文件" |
| `read_file` | 读取文件内容 | "读一下 main.rs" |
| `get_time` | 获取当前时间 | "现在几点了" |
| `recent_screenshots` | 查看最近截图 | "我刚才在看什么" |
| `send_hotkey` | 发送键盘组合键 | "帮我按 Ctrl+S" |
| `read_clipboard` | 读取剪贴板 | "剪贴板里有什么" |
| `force_foreground` | 聚焦窗口 | "切到浏览器" |
| `perform_dance` | 编排并播放舞蹈 | "跳个舞" |
| `play_dance` | 播放已保存舞蹈 | "再跳一次 happy_twist" |

其中 `launch_program`、`shell`、`send_hotkey` 三项为**危险操作**，AI 调用前会弹出权限确认。

AI 支持多轮工具调用（最多 16 轮），可以组合多个工具完成复杂任务。

## 记忆系统

8Bit Cat 有三层记忆机制，让 AI 记住你的偏好和历史对话。

### 第一层：短期对话记忆

- 记录最近的 **20 条**对话（用户消息 + AI 回复）
- 单条用户消息截断到 100 字符，AI 回复截断到 200 字符
- 注入 prompt 的总字符预算为 1500 字符
- 持久化到 `~/.ai-pad/memory/chat_summary.json`
- 每次对话时以 `[最近对话记录]...[/最近对话记录]` 注入上下文

### 第二层：长期记忆

- 通过启发式规则自动筛选值得长期保存的对话
- 触发条件：消息含"我叫/我是/我喜欢/项目/工作/明天"等关键词，或 AI 回复超过 30 字符
- 闲聊（如"喵一个"、"讲个笑话"）会被过滤，不占空间
- 最多保存 **200 条**，超限时优先淘汰已聚合的旧条目
- 检索方式：关键词匹配，按相关性排序，最多返回 10 条
- 持久化到 `~/.ai-pad/memory/long_term.json`

### 第三层：AI 聚合画像

- 当未聚合的长期记忆条目积累到 **20 条**以上，或距离上次聚合超过一定时间，自动触发聚合
- 调用 AI 将长期记忆浓缩为不超过 400 字符的用户画像
- 持久化到 `~/.ai-pad/memory/profile.json`
- 以 `[关于主人]...[/关于主人]` 注入 prompt

### 用户显式画像

你可以在 `config/user.yml` 或设置窗口中手动填写个人信息：

```yaml
name: "小明"
role: "全栈工程师"
preferences:
  - "中文交流"
  - "简洁回答"
context: "正在开发 Rust 桌面应用"
language: "zh-CN"
```

**显式画像优先级高于 AI 聚合画像**：填写了 user.yml 后，AI 聚合画像不会被注入 prompt。清空 user.yml 后自动回退到聚合画像。

## 语音输入

按住手柄 **Y** 键（或 actions.yml 中配置为 `type: voice` 的按键）进行语音输入。

### 工作原理

1. 按住 Y 键 → 屏幕中下方出现录音条窗口
2. 程序自动模拟你配置的输入法语音热键（默认 Ctrl+Win）
3. 对着麦克风说话
4. 松开 Y 键 → 程序释放热键 → 等待 700ms 让输入法完成识别
5. 识别文字自动送入 AI 对话

### 防残留机制

每次按下 Y 键时程序递增一个"generation"计数器并清空旧文本，松开后只接受当前 generation 的文本。即使上一轮语音识别的延迟回调到达，也会被自动丢弃。这确保了快速连续使用语音时不会出现文字混乱。

### 配置语音热键

在 `config/actions.yml` 中修改 `voice` 动作的 `trigger` 字段，匹配你系统输入法的语音快捷键：

```yaml
Y:
  type: voice
  voice:
    trigger: ["ctrl", "win"]   # Windows 语音输入热键
    delay: 1.0                 # 延迟秒数
```

## TTS 语音朗读

TTS 默认关闭。开启后，AI 回复完成时程序会使用 Windows 自带的 SAPI 语音合成引擎朗读。

- 使用系统默认语音（中文 Windows 默认为 Huihui 女声）
- 新的朗读会自动打断上一次未完成的朗读
- 纯本地合成，无网络依赖
- 可在设置窗口的"外观行为"标签页中开关 TTS
