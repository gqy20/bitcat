# Windows 对话验收

目前没有 Windows 设备，以下步骤**尚未执行**。它们用于下一次拿到设备后核对输入、焦点、缩放、停止和回复节奏。浏览器预览与 CI 编译不能代替这些操作。

详细场景及记录模板见[本轮验收记录](../research/chat-native-validation-2026-10-03.md)。

## 准备

在 Windows 上使用当前构建并记下 commit、Windows 和 WebView2 版本。开发构建优先执行 `make build`，用 `make run` 启动，确保随程序复制的 `config/prompts.yml` 是本轮版本。已有自定义提示词时先保留副本，不覆盖个人配置。

保持屏幕观察、摄像头及执行权限为自己的原有选择；测试受限情况时明确关闭文件读取。优先使用本地测试服务或受控示例回复；若使用真实 AI，记录模型并控制样本数量。没有服务配置时记录未执行，不把空界面当成通过。

## 单屏操作

1. 点击猫的聊天入口，用微软拼音输入“今天想慢一点”。在候选框中按 Enter，确认此时只选词；再次按 Enter 发送。用 Shift+Enter 写两行，检查中文、换行和光标。
2. 回复过程中写下一句，然后 Alt+Tab 到其他应用。观察猫的状态和文字更新是否抢焦点。回到输入框继续写，收起并重开，检查草稿与回复仍在。
3. 生成前与生成中各点一次停止。保留已输入的下一句，等停止确认后发送“先只讲第一步”。确认旧回复和旧状态不会重新覆盖它。停止不等于撤销已经开始的外部操作。
4. 显示长文、代码和宽表格，测试正文上翻、代码内部滚动、表格横向滚动。保持上翻位置等回复结束，再展开阅读、返回聊天、收起并恢复。
5. 用右下角手柄缩到约 260px 宽，输入三行并模拟发送失败。检查提示、输入与发送按钮完整可见，草稿能直接重试；双击手柄恢复自动尺寸。

将上述操作分别在 **100%、150%、200%** 缩放下重复。记录实际显示器分辨率与缩放；比较逻辑尺寸和物理尺寸时按缩放换算，不要求不同 DPI 的截图具有相同像素宽高。

## 双屏与并发

- 在两块屏幕上分别测试猫靠近上、下、左、右边缘；若副屏在主屏左侧或上方，也覆盖该负坐标排列。至少覆盖一次不同缩放组合，例如 100% 与 150%，记录各屏 DPI，核对气泡翻边、阅读展开和输入区域没有出屏。
- 一次先开文字聊天再完成语音输入，一次先开语音再发送文字；再尽量让两者接近同时完成。记录实际接受顺序，确认没有重复输入、上一段语音残留或跨轮回复覆盖。
- 读长文、选择文字和编辑草稿时，触发一条普通短通知或受控工具进度。检查阅读位置和焦点仍受到保护。工具失败或权限关闭时，需要完整的原因与下一步，不能只剩顶部的一小段省略文字。

## 回复与猫的节奏

从[十个回归场景](../research/chat-native-validation-2026-10-03.md#十个回归场景)选日常、陪伴、称呼、长文与工具结果各一例。观察文字与猫的动作是否对应：日常平稳，陪伴不过度催促，普通工具成功不反复庆祝，失败不承诺完成，结束后能自然继续交流。

本轮已取得 11 条非流式、无工具的真实模型文字样本，观察见[样本记录](../research/chat-native-validation-2026-10-03.md#真实模型文字样本)。这些样本没有验证 Windows 操作、猫的动作、资料读取或真实提醒。长文场景实际使用 JavaScript 事件循环；示例代码的输出注释已有一个顺序错误，阅读布局与内容正确性分别记录。

真实提醒成功场景同时检查本地提醒列表；失败场景使用受控结果，避免破坏自己的记录。清理测试中确实创建的提醒。单独向模型描述成功或失败，不能证明工具执行链路通过。

## 留下证据

每项填写：编号、构建与设备条件、操作、实际结果、截图或录像、相关日志时段，以及“通过 / 不通过 / 未执行”。未测的 DPI、第二块屏幕或语音组合继续写未执行。定位问题用具体描述，例如“候选框第一次 Enter 误发”，并标明发生在哪个输入或窗口状态。
