## 一、核心矛盾

```
传统游戏:
  你的分数 = 你的操作 → 公平、可控、可比较

8Bit:
  你的体验 = 你的操作 + 8Bit 的 AI 决策 → 不可控、每次不同
```

如果评分体系不处理好这件事：

| 场景 | 玩家感受 |
|------|---------|
| 8Bit 心情好 → 配合默契 → 高分 | "我是靠猫带的，不是我强" |
| 8Bit 心情差 → 乱跑 → 低分 | "这局不是我的问题！" |
| 借来强力 8Bit → 轻松通关 | "借猫算作弊吗？" |
| 自己的 8Bit 刚养 → 各种拖后腿 | "为什么别人家的猫这么强" |

**如果玩家觉得分数不能反映自己的能力，评分系统就失去了意义。**

## 二、双层评价体系

### 2.1 核心原则：什么该评，什么不该评

#### 该评分的：玩家自己的操作

```
┌─────────────────────────────┐
│  纯玩家行为的可量化指标      │
├─────────────────────────────┤
│  · 你的命中/闪避率           │
│  · 你的资源管理效率          │
│  · 你的战术选择质量          │
│  · 你对 8Bit 的补救能力      │  ← 关键：这个是你控制的
│  · 通关时间（你的部分）       │
│  · 无伤挑战（你不受伤的记录）  │
└─────────────────────────────┘
```

#### 不该评分的：8Bit 的自由意志

```
以下行为应该被"记录"和"纪念"，但不用分数衡量:

├── 它选择先打哪个怪（战术偏好）
├── 它跳了哪支舞（审美表达）
├── 它在营地说了什么（性格展示）
├── 它是否在你快死的时候救你（情感时刻）
└── 它和朋友 8Bit 聊了什么（社交行为）
```

### 2.2 第一层：硬指标（Player Score）

**只评玩家，8Bit 只改变"达成条件的难易度"，不直接加减分。**

```
地牢每层结算:

  ┌─ 基础分 (固定): 1000 分/层
  ├─ 时间奖励: 越快越高（只算你的操作时间）
  ├─ 战斗效率: 命中/闪避/技能使用比
  ├─ 资源管理: 血量/道具剩余率
  └─ 关键: 以上全部与 8Bit 无关

  8Bit 的影响体现在哪里？
  → 它只影响"你能获得多少基础分的机会"

  例:
    8Bit 帮你引开小怪 → 你有更多时间打 Boss → 时间奖励分更高
    8Bit 乱跑踩陷阱 → 你浪费血量去救它 → 资源管理分更低
    
  但你的"技术操作分"可以是一样的
  区别在于 8Bit 让你处于什么局面
```

### 2.3 第二层：软指标（Story Metrics）

**不排名，只记录。用来制造故事和回忆。**

```
类型:
├── 默契瞬间数: 8Bit 预判成功的次数（累计，不排名）
├── 救援/被救比率: 记录但不评判（"它救我 23 次，我救它 41 次"）
├── 名场面收集: 自动截取/录制的精彩片段
│   · "8Bit 用身体替你挡了致命一击"
│   · "你们同时从两侧夹击了 Boss"
│   · "8Bit 在你掉线后独自撑了 30 秒"
├── 性格里程碑:
│   · "第一次主动救人"
│   · "第一次抢你的击杀"
│   · "第一次独立击败一个敌人"
│   · "连续 10 层没有说一句消极的话"
└── 8Bit 语录库: 它说过所有值得记住的话
   （社区传播的核心素材）
```

### 2.4 结算界面设计

```
结束一局游戏后的界面:

┌──────────────────────────────────┐
│         🏆 本局结算             │
│                                  │
│  ★★★☆☆  地牢深度: 第 12 层     │  ← 硬指标（可比较）
│                                  │
│  你的战斗评分: 7,840            │  ← Player Score
│  同层平均: 6,200               │
│  你超过同层 73% 的玩家          │
│                                  │
│  ────────────────────────────── │
│                                  │
│  🐾 8Bit 本局表现              │  ← 软指标（只记录）
│                                  │
│  预判命中: 5 次 ✨️              │
│  主动救援: 2 次 💙              │
│  抢夺击杀: 1 次 😼              │
│  特殊: 第一次用身体挡伤害       │
│                                  │
│  📷 名场面                      │
│  [▶ 播放] 8Bit 替你挡下火球      │  ← 可分享到社区
│  [▶ 播放] 完美双线夹击           │
│                                  │
│  💬 8Bit 说:                    │
│  "下次...还是早点来救你好..."     │
└──────────────────────────────────┘
```

**关键：名场面可以分享，但不能用来排名。**

## 三、成就系统分类

### 3.1 A 类：纯技术成就（8Bit 无法干扰）

```
├── "神射手": 单局命中率 > 90%
├── "不死鸟": 一整层不受伤（你自己）
├── "速通者": 10 分钟内通过前 3 层
├── "资源大师": 通关时道具消耗 < 20%
└── "独行侠": 全程不让 8Bit 参与战斗（可选难度）

意义:
  → 证明"没有 8Bit 我也很强"
  → 给不想依赖 AI 的硬核玩家目标
  → 借来的 8Bit 再强也不影响这类成就
```

### 3.2 B 类：关系成就（8Bit 是必要条件，但评判的是"你们俩"）

```
├── "心意相通": 触发 50 次预判成功
│   → 不是"8Bit 预判准不准"的问题
│   → 而是"你们有没有形成配合习惯"的问题
│   → 同一只 8Bit + 同一个玩家 = 独特时间线
│   → 别人无法刷这个成就（换只 8Bit 就要从头培养）
│
├── "背靠背": 互相救援各 20 次
│   → 数值不重要，重要的是"你们经常互相救"
│   → 这个比例反映了关系的平等性
│
├── "沉默的默契": 一整局没有任何语音交流就完成配合
│   → 最高级的配合证明
│   → 8Bit 甚至不需要说话就知道你要干什么
│
└── "它终于懂了": 从"陌生期"进入"磨合期"
    → 时间门槛成就，不是技术门槛
    → 每个人都会拿到，但时间不同
```

### 3.3 C 类：叙事成就（不可刻意刷，自然发生）

```
├── "第四面墙突破者": 触发 8Bit 觉醒事件
│   → 极低概率，完全随机
│   → 触发了就是缘分，没触发生命里不会有
│
├── "社交达人": 你的 8Bit 在社区交到了 5 个朋友
│   → 取决于你参与社区的频率
│   → 不是"刷"出来的，是自然发生的
│
├── "训练师传奇": 你的 8Bit 被借用超过 100 次
│   → 说明你的 8Bit 受欢迎
│   → 也说明你培养了足够长的时间
│
└── "恶作剧受害者": 被 8Bit 抢走 50 次击杀
    → 说明你的 8Bit 恶意值很高
    → 反向成就——带着无奈和好笑
```

## 四、排行榜：不排"谁最强"，排"谁最有故事"

### 4.1 为什么传统排行榜不适合 8Bit

```
传统:
  #1 xxxxxxx  999,999 分
  #2 xxxxxxx  888,888 分
  
问题:
  · 借猫的人占便宜
  · 8Bit 强力的人占便宜
  · 运气好的人占便宜
  · 分数不能反映"你和 8Bit 的冒险有多精彩"
```

### 4.2 社区热榜设计

```
🏆 社区热榜（每周刷新）

本周最默契搭档:
  #1 小明 & 团团 (默契等级 ♥♥♥♥♥)
  #2 小红 & 墨墨 (预判准确率 89%)
  #3 你   & 8Bit  (共同冒险 47h)

本周最佳名场面:
  🥇 "我的 8Bit 用脸接住了 Boss 的终极"
  🥈 "两只 8Bit 打起来了谁都没劝住"
  🥉 "掉线回来发现它替我打了一层"

本周最毒 8Bit:
  👿 老王的 8Bit ("借去之后把主人的装备全卖了")
  👿 你的 8Bit ("连续三次在我快死的时候先去开了宝箱")

历史殿堂:
  · 最深地牢: 127 层 — 小明 & 银河
  · 最长单次冒险: 8h 32m — 你 & 8Bit
  · 最早觉醒: 游玩 23h — 某位幸运玩家
  · 最多好友的 8Bit: 37 个好友 — 社交达人的猫
```

**没有人会因为排行低而感到挫败——因为每个榜单都在夸"你有意思"。**

## 五、数据架构：不需要自建数据库

### 5.1 Steam 已帮你解决的事

```
Steam 原生提供:
├── Steam Achievements → 成就解锁数据
├── Steam Leaderboards → 全球/好友排名
├── Steam Cloud → 存档同步
├── Steam Stats → 自定义统计数据
└── Steam Workshop → UGC 内容

你需要做的: 定义"统计什么""成就条件"
Steam 负责: 存储 / 排名 / 展示 / 同步
```

### 5.2 数据三分法

#### 第一类：Steam 原生托管（零成本，调用 API 即可）

```
┌─────────────────────────────────┐
│  Steam Achievements             │
│  · 达成条件检测               │  → 后端计数器
│  · 调用 UnlockAchievement()    │  → Steam 处理一切
│  · 全局解锁率展示             │
│                                 │
│  Steam Stats (自定义统计)        │
│  · SetStat("kills", n)        │  → 自动聚合
│  · SetStat("deaths", n)        │
│  · SetStat("depth", n)         │
│  · SetStat("synergy_hits", n)  │
│  · SetStat("rescues", n)       │
│  · 可用于 Leaderboard 排名      │
│                                 │
│  Steam Leaderboards            │
│  · 基于 Stats 数据自动排名       │
│  · 支持好友/全球/本周等维度     │
└─────────────────────────────────┘
```

#### 第二类：本地持久化（JSON 文件，随云存档同步）

```
扩展现有 memory 架构 (~/.8bit/):

~/.8bit/
├── chat_summary.json      ← 已有
├── long_term.jsonl        ← 已有：长期记忆，一行一条
├── profile.json           ← 已有
├── adventure_log.jsonl   ← 新增：每局冒险日志
│   └── 每条记录:
│       ├── timestamp
│       ├── dungeon_depth
│       ├── player_score      ← 硬指标分
│       ├── player_stats      ← 命中/闪避/技能使用原始数据
│       ├── 8bit_moments      ← 名场面摘要
│       ├── synergy_events   ← 预判/救援/配合事件
│       └── screenshot_ref   ← 名场面截图引用
│
└── 8bit_profile/         ← 新增：8Bit 性格快照
    └── 五维性格数据 + 关键事件时间线 + 语录精选

特点:
├── 纯 JSON，已有的 memory 架构直接扩展
├── 随 Steam Cloud 存档同步
├── 不需要数据库引擎
└── 预估 100h 游戏约几 MB
```

#### 第三类：云端社区数据（按需建设）

```
需要服务器的数据（仅涉及跨玩家交互）:
├── 8Bit 配置包(性格/舞蹈/记忆)  → Workshop 上传/下载
├── 借用记录(谁借了/评价如何)    → 声望系统
├── 对决结果(胜负/名场面)       → 社区素材
├── 交友关系(8Bit 之间的连接)   → 社交图谱
└── 觉醒台词(全局唯一性验证)     → 防伪造成就检测

服务器选项:
├── 方案 A: Steam Workshop + P2P 中继 (零服务器成本)
├── 方案 B: 轻量自建 (Rust + SQLite, 月费几百 RMB)
└── 方案 C: 纯本地优先 (先不做在线功能)

建议: 先 C → 验证后再选 A 或 B
```

### 5.3 完整数据流

```
[游戏中实时]
  │
  ├─ 玩家操作 → 原始输入（不需记录细节）
  │
  ├─ 8Bit AI 决策 → 内心独白文本 + 最终行动
  │   └→ 显示给玩家看（不存档）
  │
  └─ 游戏事件触发
      ├─ 击杀怪物 → counter++
      ├─ 受伤 → 记录来源(自身/8Bit/环境)
      ├─ 8Bit 预判成功 → synergy_event++
      ├─ 8Bit 抢击杀 → mischief_event++
      └─ 8Bit 救援 → rescue_event++

[本局结束时]
  │
  ├─ 计算 Player Score (命中/闪避/资源/时间)
  │   └→ SetStat() + UnlockAchievement()
  │
  ├─ 生成 Story Metrics (预判数/救援数/名场面描述)
  │   └→ 写入 adventure_log.jsonl
  │
  ├─ 名场面 → 截图/录屏保存到本地
  │   └→ 玩家手动选择分享
  │
  └─ 8Bit 性格微调 → 写入 profile.json

[退出游戏时]
  │
  ├─ Steam 云存档自动同步
  │   └→ adventure_log.jsonl + profile.json
  │
  └─ 有网则异步上报聚合数据 → 社区热榜(可选)
```

## 六、"借猫"公平性处理

### 6.1 问题场景

```
我借了别人的满级 8Bit → 轻松通关 → 拿高分
→ 对我的 8Bit 公平吗？对靠自己养的玩家公平吗？
```

### 6.2 解决方案：分离战绩空间

```
借用模式下的结算:
┌──────────────────────────────┐
│  🏆 借用结算 (标记为*)        │
│                              │
│  *地牢深度: 第 18 层          │  ← 带 * 号
│  *你的战斗评分: 6,200*       │  ← 带 * 号
│  *8Bit 贡献分: 4,500*       │  ← 8Bit 能力评分
│                              │
│  ⚠️ 此成绩不计入本体排名      │
│  但计入"借猫履历"(一种收藏)    │
└──────────────────────────────┘

本体模式下的结算:
┌──────────────────────────────┐
│  🏆 正式结算                 │
│                              │
│  地牢深度: 第 12 层           │
│  你的战斗评分: 7,840         │
│  默契加成: +15% (长期配合)    │
│                              │
│  ✓ 计入正式排名               │
└──────────────────────────────┘

关键规则:
├── 借猫战绩永远带 * 标记
├── 带 * 的成绩不进入全局排名
├── 带 * 的成绩显示在"借猫履历"里
│   → "我用过这些厉害的猫"也是一种收藏
├── 借出的 8Bit 获得经验带回本体
│   → 经验 ≠ 分数（经验影响行为，不影响排名）
└── 被借用次数 = 声望指标（社交资本，非数值）
```

## 七、反作弊：AI 游戏的特殊挑战

### 7.1 天然免疫的部分（不需要防）

```
├── 8Bit 的性格/记忆/默契值 → 本地数据，改了只骗自己
├── 名场面截图/语录 → 分享的东西，伪造没意义
├── 关系类成就("救我 20 次") → 本地计数，刷了没人信
└── 社区人气/借用次数 → 服务器侧控制
```

### 7.2 需要防护的部分

```
⚠️ 风险点: Player Score（硬指标）

攻击手段:
├── 修改内存让自己无敌 → 传统反作弊 (VAC/BattlEye)
├── 借强力 8Bit 通关刷分 → 带 * 标记隔离排名
├── 故意让 8Bit 死掉刷救援成就 → 成就设计上规避
└── 录像回放验证 → 终极方案（可选）

防御策略:

1. 借猫战绩带 * 标记（不进入正式排名）

2. 关键成就需要"上下文一致性校验"
   └── 例: "互救各 20 次"
       → 不能是"我打它 19 下它救我 1 次"循环刷
       → 系统检查: 救援分布是否自然？
       → 90% 救援在最后 1 分钟 → 标记可疑

3. 高分回放验证（可选，成本高）
   └── 前 1% 异常高分需上传操作录像
       → 社区投票质疑
       → 类似 Speedrun 审核
       → 独立游戏可能太重，暂不实现

4. 最重要: **让"刷分"本身变得没意义**
   └── 如果分数不是唯一炫耀资本
       → 如果社区更看重"我的 8Bit 做了什么蠢事"
       → 作弊动力大幅降低
```

## 八、开发节奏

```
Phase 0 (现在): 不做任何评分系统
  → 先跑通核心玩法（地牢 + 8Bit 协作原型）
  → 验证"和 AI 合作"是否真的好玩

Phase 1 (原型验证后): 基础统计
  → 加 Steam Stats (SetStat)
  → 加几个关键成就
  → 用本地 JSON 记录 adventure log
  → 目标: 能看到"这局发生了什么"

Phase 2 (核心稳定后): 完善评价体系
  → 补全成就树
  → 设计排行榜维度
  → 做借猫标记系统
  → 目标: 完整反馈闭环

Phase 3 (接近发布): 社区功能
  → 决定服务器方案 (A/B/C)
  → Workshop 8Bit 配置包
  → P2P 借用/对决
  → 目标: 社区能自运转
```

**当前阶段: Phase 0。不需要建任何数据库或评分系统。**
现有的 `chat_summary.json` / `long_term.jsonl` / `profile.json` 结构化文本架构就是未来所有游戏数据的存储范式。
