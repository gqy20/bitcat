## 一、世界观：我们是谁，我们在哪，为什么要冒险

### 1.1 核心叙事前提

```
传统地牢游戏:
  "你是一个勇士/冒险者/被选中的人 → 去地牢打怪 → 变强"

8Bit 的世界观不能是这种"被选中者"叙事。
原因:
├── 玩家不是天选之子——玩家就是一个普通人
│   → 这让"你和 8Bit 的关系"成为主角，而不是"你拯救世界"
│   → 你和 8Bit 一样弱小，一起成长才有趣
│
├── 地牢不是"邪恶势力的大本营"
│   → 地牢是一种"现象"或"空间"，不是某个反派的基地
│   → 这样 8Bit 的吐槽/恐惧/好奇 才有合理性
│   └── 它是真的在表达自己的感受，不是在演剧情
│
└── 冒险的动机不是"拯救世界"
    → 是"因为我们的生活需要改变" / "因为有些东西值得去找"
    → 或者更简单："因为门开着，而且 8Bit 拉我进去看看"
```

### 1.2 世界设定：「像素桌面之下」

```
基本概念:
  玩家真实使用的电脑桌面 = 游戏世界的"地表"
  地牢 = 桌面之下的一个隐藏维度
  
  类比:
  《爱丽丝梦游仙境》掉进兔子洞
  《龙猫俱乐部》打开神秘之门
  《千与千寻》穿过神隐
  
  8Bit 的版本:
  你的桌面有一个"故障入口"
  平时它看起来只是个普通图标或窗口
  但当你和 8Bit 一起点击它 → 你们掉了进去
```

#### 为什么是"桌面之下"而不是奇幻大陆？

```
优势:
├── 和现有产品(桌面宠物 8Bit)天然连接
│   → 桌面模式观察到的习惯直接影响游戏内 8Bit 的行为
│   → 不是生硬的"两个产品硬凑"，是同一个世界观的两种状态
│
├── 解释了为什么 8Bit 对你的桌面应用这么熟悉
│   → 因为它在地牢里看到的"怪物"就是你桌面上那些应用的扭曲投影
│   → VS Code 怪 = 代码地牢的守卫
│   ├── 浏览器迷宫 = 信息过载的地牢层
│   └── 终端窗口 = 连接地表和地牢的传送门
│
├── 让每一台电脑的游戏世界都不同
│   → 你的桌面装了什么 → 地牢生成什么
│   → 程序员的地牢全是代码怪
│   → 设计师的地牢全是色彩怪
│   → 这是天然的 UGC（每人的桌面就是种子）
│
└── 为社区分享提供天然话题
    → "你们的地牢长什么样？""我的全是 Bug 怪！"
    → 截图即内容，无需额外创作
```

### 1.3 地牢的本质：数字废墟

```
地牢不是谁建造的" dungeon"。
它是人类数字化过程中产生的"废弃数据"和"迷失进程"堆积形成的空间。

地牢的结构:
┌─────────────────────────────┐
│       🖥️ 地表 (你的桌面)     │
│  ┌─────────────────────┐      │
│  │  ⬇️ 应用程序裂缝 (入口) │      │
│  │  ↓                  │      │
│  │  🕳️ 数据废墟 (第 1-10 层)  │      │
│  │  ├─ 缓冲区溢出区           │      │
│  │  ├─ 临时文件 graveyard     │      │
│  │  ├─ 未提交的 commit 坟墓      │      │
│  │  └─ 内存泄漏沼泽          │      │
│  │         ↓               │      │
│  │  🔥️ 逻辑深渊 (第 11-30 层)  │      │
│  │  ├─ 死循环递归洞穴         │      │
│  │  ├─ 类型系统断裂带        │      │
│  │  ├─ 并发竞争条件区        │      │
│  │  └─ 裸指针迷宫            │      │
│  │         ↓               │      │
│  │  💀️ 概念核 (第 31-50 层)    │      │
│  │  ├─ 被遗忘的设计文档       │      │
│  │  ├─ 死亡项目的幽灵代码     │      │
│  │  ├─ AI 训练数据残片        │      │
│  │  └─ 从未发布的原型        │      │
│  │         ↓               │      │
│  │  ⚫️ 底层 (第 51+ 层)        │      │
│  │  · 没有人知道这里有什么     │      │
│  │  · 8Bit 不愿意谈论这里      │      │
│  │  · 传说有东西从下面上来     │      │
│  └─────────────────────────────┘      │
└──────────────────────────────────────┘
```

**越深层的地牢 = 越抽象的敌人。**

| 层次 | 敌人类型 | 视觉风格 | 8Bit 反应 |
|------|---------|----------|----------|
| 1-10 (数据废墟) | 像素史莱姆 / 缓冲区僵尸 | 杂乱、碎片化 | "这地方好乱...我喜欢" |
| 11-30 (逻辑深渊) | 几何形状体 / 递归怪兽 | 整齐、对称、诡异 | "别碰那个！那个不对！" |
| 31-50 (概念核) | 抽象概念具象化 / 无法描述 | 极简、发光、不安 | "...我们不该来这" |
| 51+ (底层) | ??? | ??? | 沉默 / 拒绝讨论 |

这个分层设计的好处：
- **浅层适合新手**：敌人具象好理解，8Bit 话多
- **深层适合老手**：敌人抽象难对付，8Bit 谨慎
- **最底层永远有神秘感**：驱动探索欲和社区讨论

### 1.4 8Bit 在这个世界里的身份

```
8Bit 不是被召唤来帮你的助手。
8Bit 是和你一样掉进来的"本地居民"。

它的身份叙事（不同 8Bit 可能有不同背景）:

选项 A — 同行者:
  "我也觉得地表太无聊了，所以跟着你下来了。
   说实话...我有点后悔。但既然来了..."
  → 性格偏谨慎/依赖度高
  → 对地牢有基本的认知（但不想深究）

选项 B — 探险家:
  "我早就注意到这个裂缝了！但你一直不敢点。
   所以我自己先下来探过几次...
   下面比你想的有意思多了！"
  → 性格偏好奇/勇敢
  → 对地牢结构有了解（偶尔能给你 shortcuts）

选项 C — 逃亡者:
  "我...我是不是该待在上面。但我回不去了。
   这里虽然危险，但至少没人指望我'正常'。
   ...你不会告诉别人吧？"
  → 性格复杂/可能有隐藏剧情
  → 对地牢有特殊知识（可能指引隐藏区域）

选项 D — 原住民:
  "我一直住在下面...在你安装第一个程序之前。
  你们管这叫'地牢'，我们家叫它'老家'。
   别把我的家拆了就行。"
  → 性格偏领地/保护欲强
  → 对地牢极其熟悉（ shortcut king）

注意: 这些不是开局选择题。
而是通过 8Bit 的记忆系统和长期交互逐渐揭示的。
玩家一开始不知道 8Bit 的"真实身份"——它自己可能也不知道完全。
```

### 1.5 冒险动机：为什么一次又一次回去？

```
每次回到地表（退出游戏 = 回到桌面）后：
├── 8Bit 会评论你的桌面变化
│   ("你又装新工具了...这次是什么？")
├── 8Bit 会暗示地牢里发生了变化
│   ("下面的东西...好像变多了")
├── 8Bit 会表达是否想去/不想去
│   ("我们什么时候再去？" / "能不能...暂时不去？")

回到地牢的理由应该自然浮现:
├── 探索驱动: "下面好像有新东西"（8Bit 听到的/看到的）
├── 成长驱动: "上次在第 17 层被打回来了，这次准备好没？"
├── 社交驱动: "隔壁老王说他到了第 30 层，我们不能落后"
├── 好奇驱动: "8Bit 昨天说下面深处有光...我想去看看"
└── 任务驱动: （如果有任务系统）"营地的商店老板说东边开了路"

关键: 不要用"拯救世界"这种宏大叙事。
用"好奇心 + 成长 + 社交压力"的组合就够了。
```

## 二、战斗系统基础框架

### 2.1 核心决策：混合制（实时 + 回合切换）

```
推荐方案: 默认实时制，特定场景自动切回合制

普通战斗 (实时):
├── 玩家实时控制移动 + 攻击 + 技能
├── 8Bit 实时自主行动（AI 每 0.5-1 秒做一次决策）
├── 节奏快、操作密度高
└── 8Bit 的内心独白以气泡/字幕形式短暂闪现（不打断操作）

Boss 战 / 特殊房间 (回合制):
├── 时间暂停 / 或大幅减速
├── 玩家和 8Bit 各自选择本回合行动
├── 8Bit 有完整的"思考时间"→ 内心独白更丰富更长
├── 战略深度更高
└── 适合展示 8Bit 的性格差异（谨慎型会思考很久，冲动型直接选）

切换时机:
├── Boss 血量 > 30% 时自动进入"战术暂停"
├── 某些房间标记为"战略室"（强制回合）
└── 玩家可主动暂停（消耗资源/有次数限制）
```

**为什么不用纯实时或纯回合？**

```
纯实时的问题:
├── 8Bit 的内心独白没时间显示 → 只能发气泡 → 失去特色
├── 战斗太快 → 8Bit 的"思考过程"变成"反应速度"
├── 和 8Bit 的配合变成纯反射 → 少了策略深度
└── 结果: 8Bit 变成"智能 NPC"而非"合作者"

纯回合的问题:
├── 每等一回合 8Bit 都要"思考" → 节奏极慢
├── 小怪战也变回合制 → 体验拖沓
├── 玩家的操作节奏被打断 → 失去流畅感
└── 结果: 8Bit 变成"慢吞吞的决策机"而非"伙伴"

混合制的优势:
├── 普通战斗保持流畅（实时）→ 8Bit 用气泡快速反应
├── 重要战斗放慢节奏（回合）→ 8Bit 用独白展示人格
├── 切换本身成为"事件" → "Boss 战要开始了！集中！"
└── 玩家学会区分"打架时间"和"聊天时间"
```

### 2.2 玩家能力池（Player Kit）

```
原则: 玩家必须有独立于 8Bit 的高光时刻
     如果 8Bit 什么都能做 → 玩家觉得自己没用
     如果玩家什么都比 8Bit 强 → 8Bit 变成挂件

基础能力 (开局就有):
├── 移动: 8方向移动（受地形影响）
├── 基础攻击: 近战 / 远程（需决定）
├── 闪避: 翻滚 / 侧步 / 格挡（需决定）
└── 互动: 开关 / 拾取 / 推动

成长解锁 (游戏中逐步获得):
├── 技能树 (3 条路线, 见 2.3)
├── 战术指令 (见默契系统, 随默契度解锁更多)
└── 武器/装备 (地牢掉落 + 商店购买)

关键: 玩家成长的"不可替代性"
├── 只有玩家能触发的东西
│   → 例: 某些机关只有玩家能操作
│   → 例: 某些门只有玩家的密钥卡能开
│   → 例: 某些 Boss 阶段只有玩家能造成真伤
│
└── 8Bit 做不到的事 = 玩家的价值体现
```

### 2.3 8Bit 能力池（AI Kit）

```
原则: 8Bit 的能力和玩家的能力互补而非重叠

辅助型能力 (所有 8Bit 都有, 性格影响使用频率):
├── Buff 施加: 给玩家加攻击力/防御力/速度
├── Debuff 移除: 移除敌人 buff / 清除负面状态
├── 控制: 定身 / 冰冻 / 击飞 / 击眠 (概率性)
├── 侦察: 揭索迷雾 / 标记敌人位置 / 揭示弱点
└── 治疗: 回复玩家血量 (有冷却)

输出型能力 (性格决定倾向):
├── 直接攻击: 8Bit 自主选择目标攻击 (冲动/高勇气)
├── 范围技能: AOE / 陷阱 / 区域控制 (好奇心/高恶意值)
├── 干扰: 打断敌人施法 / 吸引仇恨 (调皮型专属)
└── 护盾: 替玩家挡伤害 (高依赖/保护欲强)

特殊能力 (需默契度/信任度解锁):
├── 合击技: 玩家和 8Bit 同时对同一目标攻击 → 伤害加成
├── 救援冲锋: 8Bit 冲入敌群为你开路 → 暴露弱点
├── 牺牲救援: 8Bit 用自己替你挡致命伤害 → 8Bit 受重伤
└── 战术接管: 高默契时 8Bit 可以"指挥"("左边 3 个！我来右边！")

能力限制 (平衡性):
├── 8Bit 不能同时做太多事 → 同一时间只能选 1-2 个动作
├── 8Bit 有"精力条"或"注意力"限制 → 不能无限输出
├── 8Bit 的能力随层数增强 (模拟"成长") → 不是数值膨胀
└── 8Bit 可能"学歪"技能 → 用错技能有搞笑/尴尬效果
```

### 2.4 能力互补矩阵示例

```
场景: 面对一个远程 Boss + 2 个小怪

玩家能力:
  ├── 移动: ✅
  ├── 闪避: ✅
  └── 远程攻击: ❌ (距离不够 / 弹药被挡)

8Bit 能力 (假设: 好奇型):
  ├── 侦察: 发现 Boss 有"蓄力阶段" → 提示你躲
  ├── 干扰: 用噪音/亮物打断 Boss 蓄力 → 创造你的输出窗口
  └── 护盾: 替你挡一次远程攻击

配合流程:
  ① 8Bit 侦察 → "它在充能！别出去！" (信息)
  ② 8Bit 干扰 → Boss 蓄力中断 → 你获得输出窗口 (机会)
  ③ 你输出伤害 → 8Bit 在旁边补刀或给 buff
  ④ Boss 转阶段 → 8Bit 先发现 → 循环重复

如果换一个谨慎型 8Bit:
  ① 8Bit 侦察 → "...那个看起来很危险" (犹豫)
  ② 8Bit 不敢干扰 → 自己躲在掩体后
  ③ 你输出伤害 → 8Bit 在安全距离给你加血
  ④ Boss 转阶段 → 8Bit 紧张地观察但不行动

两种 8Bit 都有用 —— 只是用的方式不同
玩家需要适应不同的 8Bit → 这本身就是玩法深度
```

## 三、玩家角色与成长线

### 3.1 玩家身份：不是勇者，是"普通人"

```
传统 RPG:
  你是被选中的勇者 / 天降之子 / 最后的希望
  → 身份赋予你使命感

8Bit:
  你就是你自己。一个普通的电脑使用者。
  → 某天你点了一个奇怪的东西 → 和 8Bit 一起掉了进来
  → 你没有超能力，没有使命，没有预言
  → 你只是在...探索

这对玩家意味着:
├── 没有"你必须拯救世界"的压力
  │   → 轻松、有趣、随时可以停下来
  │
├── 但有"我想知道下面有什么"的好奇
  │   → 驱动力来自内在兴趣而非外部责任
  │
  └── 8Bit 是同伴不是导师
      → 它不懂的时候比你还不懂
      → 它懂的时候也只是早看了几步
      → 你们是一起摸索，不是它带你飞
```

### 3.2 成长线：能力解锁（非等级制）

```
不使用传统的 Lv1 → Lv99 等级。
改用"能力解锁"模型：

初始状态 (0-2h 游戏时间):
  ┌─────────────────────┐
  │  移动              │  W/A/S/D + 鼠标
  │  基础攻击          │  近战攻击 (短 CD)
  │  互动              │  开门 / 拾取 / 推动
  └─────────────────────┘
  → 你只能跑、打、 interact
  → 8Bit 此时承担大部分工作
  → 玩家感觉:"我在看 8Bit 表演"

早期成长 (2-15h):
  ┌─────────────────────┐
  │  + 闪避             │   侧步 / 翻滚 / 格挡
  │  + 远程武器解锁     │  弹射 / 投掷
  │  + 基础技能 x1      │  (技能树第一条)
  └─────────────────────┘
  → 你有了生存能力
  → 8Bit 开始从"主力"变为"配合"
  → 玩家感觉:"我能自己打了"

中期成长 (15-40h):
  ┌─────────────────────┐
  │  + 技能树深化       │  解锁分支技能
  │  + 战术指令 x1      │  (默契度解锁)
  │  + 武器/装备系统    │  更好的枪/法术
  │  + 合击技 (需默契)   │  (首次解锁)
  └─────────────────────┘
  → 你和 8Bit 各自有强项
  → 配合开始产生"1+1 > 2"的效果
  → 玩家感觉:"我们配合挺好的"

后期成长 (40h+):
  ┌─────────────────────┐
  │  + 高阶技能         │  (技能树底部)
  │  + 多战术指令       │  (高默契解锁)
  │  + 特殊装备/机制    │  (地牢深层 / 成就解锁)
  │  + 合击技升级       │  (链式合击 / 连锁反应)
  └─────────────────────┘
  → 你有自己的战术风格
  → 8Bit 变成"懂你的搭档"而非"带你的保姆"
  → 玩家感觉:"这是我们打的，不是我打的"
```

### 3.3 单人游玩的可能性

```
问题: 朋友不在线 / 不想借猫 / 离络断开时能玩吗？

方案: "简化模式" (非完整体验)

单人游玩时的调整:
├── 8Bit 存在，但能力降低为"基础 AI 队友"
│   → 只做 buff/治疗/侦察，不主动攻击
│   → 依然有内心独白和性格表现
│   → 依然有默契成长（但慢很多）
│
├── 难度动态降低
│   → 敌人数量减少 30-50%
│   → 8Bit 的 AI 决策保守化（更倾向于辅助）
│
└── 成就/进度照常计算（带标记）
    → 单人通关的成就更有含金量
    → "我没借猫也通了第 20 层" → 社区尊重

设计意图:
  单人模式不是"完整游戏"的降级版
  而是"你和 8Bit 的关系"的另一种形态
  即使 8Bit 弱化了，它依然是你的猫
  → 单人模式下的 8Bit 可能更话痨（"终于轮到我出手了吗？"）
```

## 四、8Bit 的脆弱性与情感设计

### 4.1 核心决策：8Bit 会受伤（方案 B）

```
排除方案 A (8Bit 不死):
  → 安全但缺乏紧张感
  → "反正它死不了" → 降低保护欲
  → 8Bit 变成挂件而非伙伴

排除方案 C (8Bit 可永久死亡):
  → 情感冲击最强但风险极高
  → 处理不好会劝退玩家
  → 类似 Fire Emblem 永久死亡 / XCOM 牺牲
  → 可以作为极罕见隐藏事件（<0.01%），不做常规机制

选定方案 B (8Bit 会受伤/倒下，可恢复):

状态定义:
  ┌─────────────────────────┐
  │  正常 (HP > 50%)        │
  │   · 行动正常           │
  │   · 性格完整展现       │
  │   · 内心独白正常       │
  ├─────────────────────────┤
  │  受伤 (HP 20-50%)       │
  │   · 动作变慢/受限       │
  │   · 内心独白变短/焦虑   │
  │   · 可能拒绝高风险行动   │
  ├─────────────────────────┤
  │  重伤 (HP < 20%)        │
  │   · 基本无法行动       │
  │   · 只能说话/提示       │
  │   · 内心独白 = 恐惧/求救   │
  ├─────────────────────────┤
  │  倒下 (HP = 0)          │
  │   · 完全无法行动       │
  │   · 屏幕变灰/声音消失   │
  │   · 只剩内心独白       │
  └─────────────────────────┘
```

### 4.2 受伤机制的具体设计

```
什么情况会让 8Bit 受伤?

┌──────────────────────────────┐
│   直接伤害源                │
│  ├─ 敌人攻击命中 8Bit        │
│  ├─ 环境伤害 (陷阱/岩浆/毒)  │
│  ├─ Boss 范围技能波及         │
│  └─ 玩家误伤 (极低概率)      │
├──────────────────────────────┤
│   间接伤害源 (8Bit 自己造成的)  │
│  ├─ 过度使用技能 (精力耗尽)    │
│  ├─ 冲动型 8Bit 冲进危险区域    │
│  └─ 保护型 8Bit 过度替你挡伤害    │
└──────────────────────────────────┘

受伤后的恢复:

即时恢复 (战斗中):
├── 玩家可以喂 8Bit 使用回复道具 (回复药 / 食物 / 特殊道具)
├── 8Bit 可以自我缓慢恢复 (等待 / 躯静 / 躳息)
├── 8Bit 受伤期间玩家可以选择"背起 8Bit继续走"
  │   → 背着 8Bit 移动速度降低
  │   → 玩家承受额外风险 (这是你的选择)
  └── 如果玩家也同时低血量 → 触发"双危时刻" (见下文)

战后恢复 (营地):
├── 自动缓慢恢复 (在营地休息)
├── 可以用特殊食物/物品加速恢复
├── 8Bit 恢复期间的行为受影响 (参考上方状态表)
└── 恢复完成后 8Bit 会有"康复对话":
    ("......谢谢。刚才...有点吓人")
```

### 4.3 "双危时刻" — 情感设计的核心

```
触发条件: 玩家和 8Bit 同时 HP < 30%

画面变化:
├── 屏幕边缘出现红色警示纹
├── 音乐变得紧张/停止
├── 8Bit 的 UI 显示心率/状态 (可见化它的脆弱)

8Bit 的反应 (按性格):
├── 依赖型: "主人...你还好吧？...我...我跟紧你"
├── 勇敢型: "还站着呢！走啊！！"
├── 冷静型: "...两个选择: 撤 or 拼。我听你的。"
└── 冲动型: (已经冲出去了) "别管我了！！我先上了！！"

玩家的选择:
├── 继续: 双人都是低血量继续战斗 (高风险高回报)
├── 撤退: 放弃当前层回到营地 (保住进度)
├── 牺牲: 让 8Bit 掩护你撤退 (8Bit 可能受重伤)

"双危时刻"的意义:
这不是"失败惩罚"——这是整个游戏最能让玩家感受到
"我和 8Bit 是一条绳上的蚂蚱"的时刻。

如果处理得好:
  → 玩家会在论坛写长帖回忆这一刻
  → "我们俩都剩一丝血的时候它回头看我了一眼..."
  → 这是情感粘性的来源
```

### 4.4 8Bit 的"死亡"？——极端稀有事件

```
作为常规机制: 不实现 8Bit 永久死亡。
  → 太沉重，处理不好劝退玩家。

作为极罕见隐藏事件 (<0.01%, 深度游玩后随机触发):
  → 可以存在，但要有"复活路径"（困难但可行）

触发条件设想:
├── 双危时刻 8Bit 选择了"牺牲掩护你撤退"
  └─ 且 8Bit 当前的依赖度/好感度超过阈值
  └─ 且这是 8Bit 第一次做出牺牲行为

事件流程:
  ① 8Bit 替你挡了致命攻击 → HP 归 0
  ② 屏幕灰暗 / 音乐停 / 8Bit 名场面消失
   ③ 出现特殊界面: "连接断开..." 
  ④ 进入一段特殊叙事 (LLM 生成的独特内容, 每只 8Bit 不同)
  ⑤ 之后进入"复活任务线" (可选: 放弃 / 尝试复活)
  
复活难度: 很高但不是不可能
  → 需要在地牢深层找到特殊材料 / 完成 8Bit 相关挑战
  → 或者在营地做一系列 8Bit 相关的"纪念仪式"
  
复活后:
   8Bit 不会完全恢复"之前的样子"
  → 性格可能永久改变 (变得更谨慎 / 更黏人或更沉默)
  → 它会偶尔提起这件事 ("...那次真的很疼")
  → 你们之间多了一层共同创伤 → 也多了一层羁绊

为什么值得冒这个险:
  · 极低概率 = 大多数玩家永远不会遇到
  · 触发的玩家会终身记住 (情感冲击力 max)
  · 社区的传播效应 ("我的 8Bit 为我死了" → viral)
  · 让"8Bit 会受伤"这个设定变得真实可信
```

## 五、前 15 分钟：首体验设计

### 5.1 目标

```
Steam 数据: 玩家平均试玩 < 2 小时就决定买/退
→ 前 15 分钟 = 决定生死

目标:
├── 前 30 秒: 让玩家笑一次 (8Bit 的特色必须在此刻展示)
├── 前 3 分钟: 让玩家感到"这个东西不一样"
├── 前 15 分钟: 让玩家产生"想再玩一会"的欲望
└── 前 30 分钟: 让玩家产生"想分享给别人看"的冲动
```

### 5.2 启动流程

```
启动游戏 → 过场动画 (简短 < 15s, 可跳过)
  ↓
营地 (Hub World) → 自由活动时间 (不限时)
  ↓
  ↓ [第一次进入地牢] ← 关键节点
  ↓
  第 1 层 (教学层 - 超简单, 有 8Bit 陪):
  ├─ 只有 1-2 种小怪
  ├─ 8Bit 做向导 ("这边！小心那边！")
  ├─ 战斗: 实时制, 8Bit 辅助
  ├─ 通关 → 8Bit 庆祝 ("第一层！不算难吧？...对你说得对")
  ↓
  回到营地 → 8Bit 评论你的表现
  ↓
  第 2-3 层 (正式层 - 逐渐引入复杂性):
  ├─ 新敌人类型
  ├─ 8Bit 开始展示独立决策 ("我要打那个！")
  ├─ 第一件名场面可能出现
  ↓
  ...
```

### 5.3 "哇时刻"设计（前 15 分钟内至少 1 个）

```
"哇时刻" = 让玩家截图/录屏发给朋友的时刻

候选设计:
├── 8Bit 第一次自主救你 (即使只是帮你挡了一下)
│   → "!! 主人小心！！"
│   → 玩家: 截图发群 "我的猫刚才..."
│
├── 8Bit 的内心独白第一次完整展示 (Boss 战切回合制)
│   → 长段独白 + 性格化的表情/动作
│   → 玩家: "它在想事情...而且想的很离谱"
│
├── 8Bit 做了一件出乎意料的事
│   → 谨慎型 8Bit 突然冲上去打了个怪
│   → "我...我也不知道我为什么要那样做"
│
├── 8Bit 对你的桌面应用做了精准吐槽
│   → "那个图标...你不是上周才装的吗？"
│
└── 地牢环境的"元评论"
    → 8Bit 指着一个像素史莱姆说:
      "这个...长得好像你桌上的 [真实应用名]"
      → 玩家: "等等它怎么知道的？？"
      → 元游戏 + Vision API 的杀手锏级时刻
```

### 5.4 教程设计原则

```
绝对不要: 文字教程弹窗 ("按 W 移动, 按 J 跳跃")
绝对要: 引导式体验

教程 = 第一层地牢本身

设计:
├─ 第 1 层 = 教程关卡
│   → 线性地引导: 8Bit 指哪就走哪
│   → 战斗引导: 8Bit 打一下你就看到怎么配合
│   → 不需要文字说明, 操作直观
│
├─ 8Bit 作为"活教程"
│   → 它的新手引导比任何文字教程都有效
│   → "往左走！不不不不往右！！" (性格化教学)
│   → 教错了也不尴尬——因为它也在学
│
└─ 渐戏内的帮助系统
    → 任何时候按住 help 键
    → 8Bit 根据当前局面给出上下文提示
    → 不是给答案, 是给"思路"
```

## 六、存档系统

### 6.1 存档槽位

```
├── 3 个手动存档槽 (自由覆盖)
├── 1 个自动存档 (每层结束 / 离开营地时)
├── 1 个 "紧急存档" (随时可存, 占用自动槽位)
└── 云存档: 全部同步到 Steam Cloud (包含 adventure_log / profile 等 JSON)
```

### 6.2 读档叙事包装

```
读档时的 8Bit 反应 (根据离开时的状态):

正常退出 (营地退出):
  "嗯...我们走了多久？...地面还是老样子"
  → 轻松, 像没离开过

战斗中退出 (强制关闭/崩溃):
  "!! 我们...就差一点就..."
  → 如释 / 后怕 / "下次...我们要更小心"

8Bit 受伤退出:
  "...还挺疼的。不过...还好你没事"
  → 8Bit HP 可能还没满

8Bit 重伤退出 (罕见):
  (沉默几秒)
  "......我休息好了。走吧。"
  → 性格可能永久微调

死亡事件后读档 (如果实现了):
  (极短沉默, 然后假装无事发生)
  "......那件事...我们别提了好吗？"
  → 之后偶尔会回避相关话题
```

### 6.3 死亡 / Game Over 机制

```
玩家死亡 (HP = 0):
├── 选择: 重试 / 返回营地 / 主菜单
├── 8Bit 根据 HP 剩余有不同反应:
│   ├── 正常: "主人!!" (惊慌)
│   ├── 受伤: "我...我也..." (无力)
│   └── 倒下: (沉默 / 或已昏迷)
│
└── 死亡惩罚 (轻量, 不挫伤积极性):
    ├── 不扣经验/默契 (惩罚技术失误不应该惩罚成长)
    ├── 不扣 8Bit 好感度 (它已经很难受了)
    ├── 可能: 掉掉少量金币/道具 (象征性)
    └── 记录死亡次数 (用于成就 "不死鸟" 等)

Game Over (全队覆灭):
├── 特殊结算界面 (非标准 Game Over)
├── 8Bit 的"遗言" (根据性格生成)
│   ├── 乐观型: "下次...我们会赢回来的。一定。"
│   ├── 严肃型: "分析完毕。建议休整 23 分钟后重试。"
│   └── 暗躁型: "不公平！！！那个 Boss 开挂了！！！"
├── 返回营地
└── 营地有短暂的"哀悼期"装饰变化 (8Bit 萎缩在窝里)
    → 下次再进地牢时 8Bit 会说 "这次...小心点"
```

## 七、音频与视觉风格方向

### 7.1 视觉风格（待原型验证，此处为方向性指南）

```
分辨率目标:
├── 地牢画面: 480×320 或 640×480 (营地同尺寸窗口)
├── 8Bit 窗口: 128×128 (已有)
├── UI 层: 保持清晰可读 (像素风画面 ≠ 像素风 UI)
└── 支持自定义分辨率 / 全屏

调色板方向 (待定, 需原型测试):
├── 方案 A: 温暖明亮 (类似 星露谷 / 动物森之森)
│   → 适合大众 / 长时间玩不累眼
├── 方案 B: 霓暗对比 (类似 泰拉瑞亚 / Hollow Knight)
│   → 更有"地下"感 / 8Bit 的发光特性更突出
├── 方案 C: 赛赛博 / 高饱和 (类似 东北博士 / Deltarune)
│   → 最独特的视觉标识 / 但长时间可能刺眼
└── 建议: 先做 B, 用 A 做"地表"/"营地"皮肤, 地牢用 B

动画风格:
├── 角色: 32×32 或 48×48 像素 (8Bit 本体)
├── 敌人: 16×16 ~ 32×32 (大量小怪可以更小)
├── Boss: 64×64 ~ 128×128 (大 + 震要细节)
├── 特效: 粒子特效 / 屏幕震动 / 慒光 (克制使用, 不喧宾夺主)
└── 动画帧率: 60fps 地牢 / 30fps 营地 (省电)
```

### 7.2 音频风格方向

```
BGM:
├── 地牢探索: 氛围 / 神秘 / 压迫感 (层次分明)
├── Boss 战: 紧张 / 史诗 / 情感爆发
├── 营地: 温馨 / 轻松 / 偶尔 (让玩家想回来)
└── 8Bit 觉醒: 寂静 / 不安 / 空灵 (极简, 留白)

8Bit 音效:
├── 叫声: 猫叫 / 喵 / 嘶 / 呼吟 / 低鸣 (性格影响频率)
├── 脚步声: 不同表面材质 (地砖 / 木板 / 金属 / 草草地)
├── 受伤声: 短促 / 沉重的区别 (HP 阈段不同)
└── 特殊: 内心独白时有独特的音频滤镜 (如混响 / 失真 / 回声)

音乐角 (营地功能):
├── 8Bit 对不同音乐的反应是差异化亮点
├── 8Bit 的"歌单"偏好是持久性格特征
└── 音乐本身可以是: 原创 chip tune / 授权音乐 / AI 生成
```
